## Фича 1 — «🔥 Горящие события»

### Суть
Горизонтальная полоса карточек в верхней части страницы событий.
Показывает мероприятия, которые **начнутся в ближайшие 72 часа** и **заполнены на 50%+** по участникам.
Каждая карточка содержит живой **обратный отсчёт** до начала события и **шкалу заполненности**.

### Бизнес-логика
- Событие «горящее», если:
  - `status = 'Активное'`
  - `start_date` — от текущего момента до +72 часов
  - `max_participants IS NOT NULL AND max_participants > 0`
  - `(участников / max_participants) * 100 >= 50`
- Отображается не более 10 событий, отсортированных по ближайшей дате начала.
- Компонент исчезает, если API вернул пустой массив.

### Backend

**Файл:** `back_xaxaton2025/handlers/discover.go`

**Структура ответа:**
```go
type HotEventResponse struct {
    dto.EventResponse          // стандартное событие
    FillPercent float64 `json:"fillPercent"` // % заполненности, 0.0-100.0
    HoursLeft   float64 `json:"hoursLeft"`   // часов до начала
}
```

**Маршрут:** `GET /api/events/hot`  
**Авторизация:** не требуется (публичный)  
**Кэш:** нет (данные меняются в реальном времени)

**Алгоритм хендлера:**
1. Получить `now = time.Now().UTC()`, `deadline = now + 72h`
2. Запрос к БД: события с нужными условиями + `Preload("Participants", "Categories", "Organizer")`
3. Для каждого события вычислить `fillPercent = len(participants) / maxParticipants * 100`
4. Отфильтровать `fillPercent < 50`
5. Вычислить `hoursLeft = max(0, startDate - now).Hours()`
6. Вернуть `[]HotEventResponse`

### Frontend

**API-слой:**
- `src/modules/events/api/requests/getHotEvents.ts` — `GET events/hot`
- `src/modules/events/api/hooks/useGetHotEventsQuery.ts` — react-query hook, `staleTime=60s`, `refetchInterval=60s`

**Компонент:** `src/modules/events/ui/HotEventsStrip.tsx`
- Горизонтальный скролл (`overflow-x-auto`, `scrollbar-hide`)
- Каждая карточка `HotCard`:
  - Фоновое изображение события
  - Бейдж «🔥 Горит» (оранжевый, верхний-левый угол)
  - Живой таймер обратного отсчёта (хук `useCountdown`, обновляется раз в секунду через `setInterval`)
  - Прогресс-бар заполненности (цвет: жёлтый < 70%, оранжевый < 90%, красный ≥ 90%)
  - Текст `N / M участников`
- Скелетон при загрузке (3 пульсирующих блока)
- Если `events.length === 0` — компонент не рендерится

**Интеграция:**
В `EventsPage.tsx` добавить над датной полосой:
```tsx
<HotEventsStrip />
```

## Фича 2 — «✨ Рекомендовано для вас»

### Суть
Сетка из до 6 персонализированных карточек событий.
Доступна **только авторизованным** пользователям.
Можно свернуть кликом по заголовку.
Релевантность рассчитывается на основе **весовых интересов** пользователя.

### Бизнес-логика
- Берём активные события с `start_date > now`
- Исключаем события, в которых пользователь **уже участвует**
- Для каждого события считаем `relevanceScore`:
  - +`weight * 2` за каждый **тег** события, совпадающий с именем интереса пользователя
  - +`weight * 3` за каждую **категорию** события, совпадающую с именем интереса
  - Нормализуем до диапазона 0-100
  - Прибавляем «поп-бонус»: +5 за каждые 10 участников, но не более +20
- Если у пользователя **нет интересов** — показываем самые популярные события (по числу участников)
- Возвращаем топ-6 по убыванию `relevanceScore`

### Backend

**Файл:** `back_xaxaton2025/handlers/discover.go`

**Структура ответа:**
```go
type RecommendedEventResponse struct {
    dto.EventResponse
    RelevanceScore   float64  `json:"relevanceScore"`   // 0.0-100.0
    MatchedInterests []string `json:"matchedInterests"` // имена совпавших интересов
}
```

**Маршрут:** `GET /api/events/recommended`  
**Авторизация:** требуется JWT Bearer  
**Кэш:** нет

**Алгоритм хендлера:**
1. Получить `userID` из контекста Gin
2. Загрузить `UserInterest` с `Preload("Interest")` для этого пользователя → map `{name: weight}`
3. Загрузить будущие активные события (limit 50)
4. Найти ID событий, где пользователь уже участник → set `participatingSet`
5. Для каждого события (не в `participatingSet`):
   - Если интересов нет → score = min(count*2, 50)
   - Иначе считать совпадения по тегам и категориям
   - Если totalScore == 0 → пропустить
   - Нормализовать: `normalized = min(totalScore/150 * 100, 100)`
   - Итог: `min(normalized + popBonus, 100.0)`
6. Сортировать по убыванию, взять первые 6
7. Вернуть `[]RecommendedEventResponse`

### Frontend

**API-слой:**
- `src/modules/events/api/requests/getRecommendedEvents.ts` — `GET events/recommended`
- `src/modules/events/api/hooks/useGetRecommendedEventsQuery.ts` — принимает `enabled: boolean`, `staleTime=120s`

**Компонент:** `src/modules/events/ui/RecommendedEvents.tsx`
- Props: `{ isAuth: boolean }`
- Если `!isAuth` или `events.length === 0` — не рендерится
- Заголовок кликабельный — сворачивает/разворачивает секцию
- Отображает кол-во рекомендаций в пилюле рядом с заголовком
- Сетка: 1 col mobile, 2 col sm, 3 col lg
- Каждая карточка `RecommendCard`:
  - Миниатюра 80×80px (слева)
  - Название + краткое описание
  - Дата начала
  - Бейдж релевантности: зелёный ≥ 70%, жёлтый ≥ 40%, серый < 40%
  - Теги совпавших интересов (до 3 штук)
- Скелетон при загрузке

**Интеграция:**
В `EventsPage.tsx` добавить под `<HotEventsStrip />`:
```tsx
<RecommendedEvents isAuth={isAuth} />
```

## Маршруты (регистрация)

**Файл:** `back_xaxaton2025/routes/routes.go`

Добавить **до** `events.GET("")` в группе `/api/events`:
```go
discoverHandler := handlers.NewDiscoverHandler()
// ...
events.GET("/hot", discoverHandler.GetHotEvents)
events.GET("/recommended", middleware.AuthMiddleware(), discoverHandler.GetRecommendedEvents)
```

> ⚠️ Маршруты `/hot` и `/recommended` должны быть объявлены **до** `/:id`, иначе Gin захватит их как параметр.
