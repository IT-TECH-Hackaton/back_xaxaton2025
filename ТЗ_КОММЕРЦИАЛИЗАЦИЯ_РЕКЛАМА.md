# Техническое задание: Коммерциализация рекламы MyAfisha

## Обзор

Полный цикл монетизации через рекламу: от заявки пользователя на статус рекламодателя до размещения баннеров в ленте с одобрением администратором и оплатой.

---

## 1. Роли и состояния

### 1.1 Роли пользователей

| Роль | Описание |
|------|----------|
| Пользователь | Обычный пользователь, может просматривать события и участвовать |
| Рекламодатель | Может создавать рекламные кампании, баннеры; доступ к кабинету рекламодателя |
| Администратор | Управление пользователями, одобрение заявок на рекламодателя, модерация баннеров |

### 1.2 Состояния заявки на рекламодателя

| Состояние | Описание |
|-----------|----------|
| `pending` | Заявка подана, ожидает рассмотрения админом |
| `approved` | Админ одобрил, пользователю назначена роль Рекламодатель |
| `rejected` | Админ отклонил заявку |

### 1.3 Состояния баннера

| Состояние | Описание |
|-----------|----------|
| `draft` | Создан рекламодателем, не отправлен на модерацию |
| `pending_review` | Отправлен на модерацию, ожидает одобрения админа |
| `approved` | Админ одобрил, баннер готов к оплате и показу |
| `rejected` | Админ отклонил (с причиной) |
| `active` | Оплачен, показывается в ленте |
| `paused` | Приостановлен рекламодателем |
| `finished` | Достигнут лимит показов |

---

## 2. Поток: Заявка на статус рекламодателя

### 2.1 Действия пользователя

1. Пользователь авторизован (роль «Пользователь»).
2. В профиле или на странице «Рекламодателям» (Footer) видит кнопку **«Стать рекламодателем»**.
3. Нажимает → открывается форма заявки:
   - Контактное имя (или берётся из профиля)
   - Email (из профиля, readonly)
   - Телефон (опционально)
   - Комментарий / цель рекламы (textarea, опционально)
4. Отправляет заявку → POST `/api/advertiser/request`.

### 2.2 Backend

**Модель `AdvertiserRequest`:**

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | PK |
| user_id | UUID | FK → users |
| status | enum | pending, approved, rejected |
| comment | text | Комментарий пользователя |
| admin_comment | text | Комментарий админа при отклонении |
| created_at | timestamp | |
| updated_at | timestamp | |

**API:**

- `POST /api/advertiser/request` — создать заявку (только для пользователей без роли Рекламодатель, не более 1 активной заявки в pending).
- `GET /api/advertiser/request/status` — проверить статус своей заявки (для пользователя).

### 2.3 Действия администратора

1. Админ заходит в раздел **«Заявки на рекламодателя»** (новая вкладка в AdminPage).
2. Видит список заявок со статусом `pending`.
3. Для каждой заявки:
   - **Одобрить** → пользователю назначается роль `Рекламодатель`, статус заявки `approved`.
   - **Отклонить** → вводит причину в `admin_comment`, статус `rejected`.

**API (admin):**

- `GET /api/admin/advertiser-requests` — список заявок (фильтр по status).
- `POST /api/admin/advertiser-requests/:id/approve` — одобрить.
- `POST /api/admin/advertiser-requests/:id/reject` — отклонить (body: `{ "reason": "..." }`).

---

## 3. Поток: Создание и модерация баннера

### 3.1 Действия рекламодателя

1. Рекламодатель заходит в **Кабинет рекламодателя** (`/ads`).
2. Нажимает **«Создать баннер»**.
3. Заполняет форму:
   - **URL изображения** (обязательно) — баннер 1200×400 px (или иной формат по ТЗ).
   - **Ссылка при клике** (обязательно) — куда ведёт баннер.
   - **Заголовок** (опционально).
   - **Целевое количество показов** (обязательно) — например 1000, 5000, 10000.
   - **Цена** (обязательно) — в рублях. Может быть предзаполнена из прайс-листа.
4. Сохраняет как **черновик** или **отправить на модерацию**.
5. Если отправил на модерацию → статус баннера `pending_review`.

### 3.2 Прайс-лист (тарифы на рекламу)

Админ задаёт тарифы в настройках (или через отдельную сущность `AdPricePlan`):

| Показов | Цена (₽) | Цена за 1000 показов |
|---------|----------|----------------------|
| 1000 | 500 | 500 |
| 5000 | 2000 | 400 |
| 10000 | 3500 | 350 |
| 25000 | 7500 | 300 |

На фронте рекламодатель может выбрать план из выпадающего списка — подставляются `targetImpressions` и `price`.

### 3.3 Действия администратора (модерация баннера)

1. Админ заходит в раздел **«Модерация баннеров»** (или «Реклама» в AdminPage).
2. Видит баннеры со статусом `pending_review`.
3. Для каждого баннера:
   - Просматривает превью (изображение, ссылку, заголовок).
   - **Одобрить** → статус `approved`. Баннер появляется в списке «Ожидают оплаты».
   - **Отклонить** → вводит причину, статус `rejected`. Рекламодатель видит причину в кабинете.

**API (admin):**

- `GET /api/admin/banners` — все баннеры с фильтром по статусу.
- `POST /api/admin/banners/:id/approve` — одобрить.
- `POST /api/admin/banners/:id/reject` — отклонить (body: `{ "reason": "..." }`).

### 3.4 Оплата баннера

1. После одобрения баннер имеет статус `approved`.
2. Рекламодатель в кабинете видит кнопку **«Оплатить»** рядом с баннером.
3. Нажимает → переход на страницу оплаты (интеграция ЮKassa/CloudPayments).
4. После успешной оплаты:
   - Статус баннера → `active`.
   - Баннер начинает показываться в ленте событий.

**Модель оплаты:** `AdPayment` — связь баннера с платёжной транзакцией (id, banner_id, amount, status, payment_id от провайдера, created_at).

---

## 4. Размещение баннеров в ленте

### 4.1 Правила показа

- Баннеры со статусом `active` и `impressions < target_impressions`.
- Частота: **1 баннер на каждые 12 карточек событий** (как сейчас).
- Порядок: по дате создания (или по приоритету, если добавить поле `priority`).
- После достижения `target_impressions` → статус `finished`, баннер перестаёт показываться.

### 4.2 Внешний вид баннера

- Формат: карточка того же размера, что и EventCard (или шире — на всю ширину грида).
- Содержимое: изображение (кликабельное), опционально заголовок поверх.
- Подпись «Реклама» мелким шрифтом (требование ФЗ о рекламе).
- При клике: переход по `linkURL` + запись клика (POST `/ads/:id/click`).
- При показе: запись показа (POST `/ads/:id/impression`).

## 6. План реализации (пошагово)

### Этап 1: Заявка на рекламодателя

1. Создать модель `AdvertiserRequest`, миграция.
2. Handlers: `POST /api/advertiser/request`, `GET /api/advertiser/request/status`.
3. Admin handlers: `GET/POST approve/reject` для заявок.
4. Frontend: форма «Стать рекламодателем», страница админа «Заявки на рекламодателя».

### Этап 2: Модерация баннеров

1. Расширить `AdBanner` полями `status` (draft, pending_review, approved, rejected, active, …), `rejection_reason`, `approved_at`.
2. Изменить `CreateBanner`: по умолчанию `draft` или `pending_review` (на выбор).
3. Admin handlers: `GET /api/admin/banners`, `POST approve`, `POST reject`.
4. Frontend: раздел модерации баннеров в AdminPage, обновить форму создания баннера (кнопки «Сохранить черновик» / «Отправить на модерацию»).

### Этап 3: Прайс-лист и тарифы

1. Создать `AdPricePlan` или конфиг с тарифами.
2. API: `GET /api/ads/price-plans` — публичный список тарифов.
3. Frontend: при создании баннера — выбор тарифа из списка, автоподстановка `targetImpressions` и `price`.

### Этап 4: Оплата

1. Интеграция ЮKassa: создание платежа, webhook для подтверждения.
2. Модель `AdPayment`, handler для webhook.
3. Frontend: кнопка «Оплатить» → редирект на платёжную форму, страница успеха/ошибки.
4. После успешной оплаты: обновить `ad_banners.status = active`, `paid_at = now()`.

### Этап 5: Полировка

1. Уведомления: email рекламодателю при одобрении/отклонении заявки и баннера.
2. Лимиты: не более N активных баннеров у одного рекламодателя.
3. Аудит: логирование действий админа (кто одобрил/отклонил, когда).

## 7. Сводная схема потоков

```
Пользователь                    Админ                         Система
     |                            |                               |
     |-- Заявка на рекламодателя ->|                               |
     |                            |-- Одобрить/Отклонить --------->| Роль Рекламодатель
     |<-- Уведомление ------------|                               |
     |                            |                               |
     |-- Создать баннер (draft) ->|                               |
     |-- Отправить на модерацию ->|                               |
     |                            |-- Просмотр баннеров           |
     |                            |-- Одобрить/Отклонить --------->| status=approved
     |<-- Уведомление ------------|                               |
     |                            |                               |
     |-- Оплатить баннер -------->|----------------------------->| ЮKassa
     |<-- Успешная оплата -------|----------------------------->| status=active
     |                            |                               |
     |                            |                    Показ в ленте (1 на 12 карточек)
```
