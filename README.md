# Bekend Backend - Система электронной афиши

Бекенд для системы электронной афиши на Go с полной функциональностью авторизации, управления событиями и администрирования.

## 🚀 Технологии

- **Go 1.23** - Язык программирования
- **Gin** - Веб-фреймворк
- **GORM** - ORM для работы с БД
- **PostgreSQL 15** - База данных
- **JWT (golang-jwt/jwt/v5)** - Аутентификация
- **bcrypt (golang.org/x/crypto)** - Хеширование паролей
- **gomail** - Отправка email (Yandex)
- **Docker + docker-compose** - Контейнеризация
- **github.com/xuri/excelize/v2** - Экспорт в XLSX
- **github.com/robfig/cron/v3** - Cron задачи

## 📦 Быстрый старт

### 1. Настройка .env файла

Создайте `.env` файл из `env.template`:

```bash
cp env.template .env
```

Заполните обязательные поля:
```env
EMAIL_USER=your-email@yandex.ru
EMAIL_PASSWORD=your-password
EMAIL_FROM=your-email@yandex.ru
JWT_SECRET=your-secret-key-min-32-characters-long
```

**Важно:** Включите IMAP в настройках Yandex почты:
- https://mail.yandex.ru → Настройки → Почтовые программы → IMAP

**Платежи (ЮKassa):** для приёма оплаты задайте в `.env`:
```env
YOOKASSA_SHOP_ID=ваш-shop-id
YOOKASSA_SECRET_KEY=ваш-секретный-ключ
BACKEND_URL=http://localhost:8081
```
Webhook URL для настройки в личном кабинете ЮKassa: `{BACKEND_URL}/api/payments/webhook/yookassa`

**Полный сид (тестовые данные):** для загрузки 100+ пользователей и 100+ афиш при старте:
```env
SEED_FULL=true
```
Или запустите вручную: `go run ./scripts/seed_full.go`

### 2. Запуск через Docker

```bash
docker-compose up -d
```

### 3. Создание администратора

```bash
# Администратор создается автоматически при первом запуске (email: admin@admin.com, password: Admin123!)
# Для создания дополнительных администраторов используйте API:
# POST /api/admin/users с role: "Администратор"
```

### 4. Проверка работы

- Health check: http://localhost:8081/health
- API: http://localhost:8081/api

## 📚 Полная документация API

### 🔐 Авторизация

#### POST /api/auth/register
Регистрация нового пользователя.

**Тело запроса:**
```json
{
  "fullName": "Иванов Иван Иванович",
  "email": "user@example.com",
  "password": "Password123!",
  "passwordConfirm": "Password123!"
}
```

**Валидация:**
- `fullName`: только русские буквы, 2-100 символов
- `email`: валидный формат email, уникальный
- `password`: минимум 8 символов, латинские буквы, цифры, спецсимволы
- `passwordConfirm`: должно совпадать с password

**Ответ:**
```json
{
  "message": "Код подтверждения отправлен на почту"
}
```

**Статусы:**
- `200` - Успешно, код отправлен
- `400` - Ошибка валидации
- `409` - Пользователь с таким email уже существует

---

#### POST /api/auth/verify-email
Подтверждение email по коду.

**Тело запроса:**
```json
{
  "email": "user@example.com",
  "code": "123456"
}
```

**Валидация:**
- `code`: 6 цифр (000000-999999)
- Код действителен 10 минут

**Ответ:**
```json
{
  "token": "jwt_token_here",
  "user": {
    "id": "uuid",
    "email": "user@example.com",
    "role": "Пользователь"
  }
}
```

**Статусы:**
- `200` - Email подтвержден, токен выдан
- `400` - Неверный или истекший код

### 👤 Пользователь

#### GET /api/user/profile
Получить профиль текущего пользователя.

**Требуется:** Токен

**Ответ:**
```json
{
  "uid": "uuid",
  "firstName": "",
```

**Примечания:**

- `image` - URL аватарки пользователя (может быть null)
- `telegram` - Telegram username без символа @

**Статусы:**
- `200` - Успешно
- `401` - Требуется авторизация
- `404` - Пользователь не найден

#### PUT /api/user/profile
Обновить профиль пользователя.

**Требуется:** Токен

**Формат:** `multipart/form-data`

**Параметры:**
- `fullName` (необязательное) - ФИО пользователя
- `telegram` (необязательное) - Telegram username (можно с @ или без)
- `avatar` (необязательное) - файл изображения для аватарки

**Валидация:**
- `fullName`: только русские буквы, 2-100 символов
- `telegram`: 5-32 символа, латинские буквы, цифры, подчеркивания (символ @ удаляется автоматически)
- `avatar`: файл изображения (jpg, jpeg, png, gif, webp), максимум 10MB

**Примеры использования:**

**1. Обновить профиль с аватаром:**
```bash
PUT /api/user/profile
Content-Type: multipart/form-data

fullName: "Иванов Иван Иванович"
telegram: "@username"
avatar: [файл изображения]
```

**2. Обновить только ФИО и Telegram (без аватара):**
```bash
PUT /api/user/profile
Content-Type: multipart/form-data

fullName: "Иванов Иван Иванович"
telegram: "@username"
```

**3. Обновить только аватар:**
```bash
PUT /api/user/profile
Content-Type: multipart/form-data

avatar: [файл изображения]
```

**4. Обновить только ФИО:**
```bash
PUT /api/user/profile
Content-Type: multipart/form-data

fullName: "Иванов Иван Иванович"
```

**Ответ:**
```json
{
  "message": "Профиль обновлен",
  "user": {
    "uid": "uuid",
    "firstName": "",
    "secondName": "",
    "mail": "user@example.com",
    "phone": "",
    "tags": ["интерес1", "интерес2"],
    "birthDate": "",
    "image": "/uploads/avatars/uuid_timestamp.jpg",
    "telegram": "username",
    "role": "Пользователь",
    "fullName": "Иванов Иван Иванович"
  }
}
```

**Примечания:**
- Аватар сохраняется в папку `uploads/avatars/`
- Старый файл аватара автоматически удаляется при загрузке нового
- URL аватара сохраняется в БД в поле `avatarURL`
- Файлы доступны по пути `/uploads/avatars/filename`

**Статусы:**
- `200` - Профиль обновлен
- `400` - Ошибка валидации или не указаны поля для обновления
- `401` - Требуется авторизация
- `404` - Пользователь не найден

### 📅 События

#### GET /api/events
Получить список событий с фильтрацией и пагинацией.

**Параметры запроса:**
- `tab` - тип фильтрации:
  - `active` - активные события
  - `my` - мои события (требуется токен)
  - `past` - прошедшие события
  - без параметра - "мои события" (если авторизован)
- `page` - номер страницы (по умолчанию: 1)
- `limit` - количество элементов на странице (по умолчанию: 20, максимум: 100)
- `search` - поиск по названию и описанию (1-200 символов)
- `categoryIDs` - фильтр по категориям (массив UUID, можно указать несколько: `?categoryIDs=uuid1&categoryIDs=uuid2`)
- `tags` - фильтр по тегам (массив строк, можно указать несколько: `?tags=тег1&tags=тег2`)
- `dateFrom` - фильтр по дате начала (формат: YYYY-MM-DD)
- `dateTo` - фильтр по дате окончания (формат: YYYY-MM-DD)
- `sortBy` - сортировка: `startDate` (по умолчанию), `createdAt`, `participantsCount`
- `sortOrder` - порядок сортировки: `ASC` (по умолчанию), `DESC`

**Требуется:** Токен для `tab=my` или без параметра

**Пример запроса:**
```
GET /api/events?tab=active&page=1&limit=20&search=концерт&categoryIDs=uuid1&tags=музыка&dateFrom=2024-01-01&dateTo=2024-12-31&sortBy=startDate&sortOrder=ASC
```

```json
      "maxParticipants": 50,
      "status": "Активное",
      "participantsCount": 15,
      "categories": [
        {
          "id": "uuid",
          "name": "Концерты",
          "description": "Описание категории"
        }
      ],
      "tags": ["музыка", "концерт", "живая музыка"],
      "address": "Москва, Красная площадь, 1",
      "latitude": 55.7539,

      "organizer": {
```

**Статусы:**

#### POST /api/events
Создать новое событие.

**Требуется:** Токен

**Тело запроса:**
```json
{
  "title": "Название события",
  "shortDescription": "Краткое описание",
  "fullDescription": "Полное описание",
  "startDate": "2024-12-20T10:00:00Z",
  "endDate": "2024-12-20T18:00:00Z",
  "imageURL": "/uploads/image.jpg",
  "paymentInfo": "Информация об оплате",
  "maxParticipants": 50,
  "participantIDs": ["uuid1", "uuid2"],
  "categoryIDs": ["uuid1", "uuid2"],
  "tags": ["тег1", "тег2", "тег3"],
  "address": "Москва, Красная площадь, 1",
  "latitude": 55.7539,
  "longitude": 37.6208,
  "yandexMapLink": "https://yandex.ru/maps/?pt=37.6208,55.7539&z=16"
}
```

**Валидация:**
- `title`: обязательное, 1-200 символов
- `fullDescription`: обязательное, 1-5000 символов
- `shortDescription`: необязательное, 1-500 символов
- `startDate`: обязательное, должна быть в будущем
- `endDate`: обязательное, должна быть позже startDate
- `imageURL`: обязательное
- `maxParticipants`: необязательное, должно быть > 0
- `categoryIDs`: необязательное, массив UUID категорий
- `tags`: необязательное, массив строк (теги события)
- `address`: необязательное, до 500 символов
- `latitude`: необязательное, от -90 до 90
- `longitude`: необязательное, от -180 до 180
- `yandexMapLink`: необязательное, до 1000 символов

**Ответ:**
```json
{
  "id": "uuid",
  "message": "Событие создано"
}
```

**Статусы:**
- `200` - Событие создано
- `400` - Ошибка валидации
- `401` - Требуется авторизация

### 🛡️ Администрирование

#### POST /api/admin/users
Создать нового пользователя (включая администраторов).

**Требуется:** Токен администратора

**Тело запроса:**
```json
{
  "fullName": "Иванов Иван Иванович",
  "email": "newuser@example.com",
  "password": "Password123!",
  "role": "Администратор"
}
```

**Валидация:**
- `fullName`: обязательное, только русские буквы, 2-100 символов
- `email`: обязательное, валидный формат email, уникальный
- `password`: обязательное, минимум 8 символов, латинские буквы, цифры, спецсимволы
- `role`: необязательное, "Пользователь" или "Администратор" (по умолчанию "Пользователь")

**Ответ:**
```json
{
  "message": "Пользователь успешно создан",
  "user": {
    "id": "uuid",
    "email": "newuser@example.com",
    "fullName": "Иванов Иван Иванович",
    "role": "Администратор"
  }
}
```

**Статусы:**
- `201` - Пользователь создан
- `400` - Ошибка валидации
- `401` - Требуется авторизация
- `403` - Требуются права администратора
- `409` - Пользователь с таким email уже существует

## 🔐 Авторизация

Все защищенные эндпоинты требуют заголовок:
```
Authorization: Bearer <token>
```

Токен выдается при:
- Успешном входе (`POST /api/auth/login`)
- Подтверждении email (`POST /api/auth/verify-email`)
- Авторизации через Яндекс (`GET /api/auth/yandex/callback` или `POST /api/auth/yandex/fake`)

---

## 📊 Статусы событий

- **Активное** - текущая дата между startDate и endDate
- **Прошедшее** - текущая дата > endDate
- **Отклоненное** - видно только администраторам

Статусы обновляются автоматически через cron (каждый час).

## 🔔 Email уведомления

Система отправляет email уведомления:

1. **При регистрации:**
   - Код подтверждения email
   - Приветственное письмо после подтверждения

2. **При восстановлении пароля:**
   - Ссылка для сброса пароля (действительна 24 часа)
   - Уведомление об изменении пароля

3. **При событиях:**
   - Уведомление организатору при участии/отмене участия
   - Уведомление всем участникам при создании события
   - Уведомление всем участникам об изменении события
   - Напоминание за 24 часа до начала (cron, раз в день)

4. **Администратором:**
   - Отправка нового пароля при сбросе
